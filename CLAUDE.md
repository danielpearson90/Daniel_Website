# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Static personal academic website for Daniel Pearson, generated by a stdlib-only Python script. `README.md` covers
content editing, `SPEC.md` is the design brief and build contract, and `templates/MARKUP.md` documents the exact HTML
each page and entry type produces. Read `SPEC.md` before changing design or markup; its constraints are deliberate.

## Commands

Python 3.11+ is required (`tomllib`). On this machine the default `python3` on PATH may be the system 3.9, which fails
with `ModuleNotFoundError: No module named 'tomllib'`; use `/opt/homebrew/bin/python3` (3.14) instead.

```
python3 build.py --check        # parse and validate all content, print a summary, write nothing
python3 build.py                # wipe and regenerate dist/
python3 -m http.server -d dist  # preview at http://localhost:8000
DEPLOY_HOST=<server> DEPLOY_PATH=/var/www/site deploy/deploy.sh [--dry-run]   # build + rsync --delete
```

There are no tests, linters or dependencies. `--check` is the verification step after any content or parser change;
after rendering changes, build and inspect the output in `dist/` (gitignored).

## Architecture

`build.py` runs in two stages. The data layer (`load_all()` and the `load_*` functions) reads every file in
`content/`, validates TOML tables against required/optional key types, parses BibTeX, and groups publications, talks
and news by year. Any malformed content raises `ContentError`, which `main()` turns into a one-line error and exit
code 1. The render layer is a set of small HTML-string helpers (`group`, `entries`, `p`, `a`, ...) and one
`render_<page>` function per page; `PAGES` maps output file to renderer and meta description, and `build_site()`
wraps each page in `templates/base.html` via `string.Template` (`$`-placeholders). The docstring at the top of
`build.py` saying rendering is a stub is out of date.

`bibtex.py` is a minimal hand-written BibTeX parser (nested braces, LaTeX accents, `--` to en dash) plus
`parse_authors`. The site owner is marked in bib files as `{\myname{pearson}}` and rendered bold using
`owner_short` from `site.toml`. Research projects reference publications by bib key (`papers` in `projects.toml`),
and the loader rejects unknown keys.

Conventions that span files:

- All content text is HTML-escaped except fields documented as inline HTML: news `text`, `site.toml` bio paragraphs,
  and project `description`.
- All links are relative so the site works from any directory. `static/` is copied to `dist/static/`, and content
  paths like `files/cv.pdf` get a `static/` prefix at build time (`local_url`). A `pdf` field must point at a file
  that exists in `static/files/`.
- Canonical links and `sitemap.xml` are emitted only when `base_url` in `site.toml` is non-empty.
- Every page uses the same `section.group` layout (label column + body column); new page types should reuse it
  rather than introduce new layout patterns.
- Design constraints from `SPEC.md`: no JavaScript, no external requests (fonts self-hosted in `static/fonts/`),
  monochrome only with colours as custom properties on `:root`, dark mode via `prefers-color-scheme`, exactly one
  image (the portrait), no cards, boxes, shadows or icons.
- Text in `[square brackets]` in content files is a placeholder awaiting real information.
